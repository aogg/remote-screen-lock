## 1. 多显示器

**默认策略（一期）**：锁定窗口覆盖所有显示器（每个显示器一个全屏置顶窗口）；**主显示器**渲染内容（时钟/图片），**其余显示器纯黑**。避免副屏内容干扰，也降低多屏渲染成本。

| 情形 | 期望行为 | 验收标准 |
| --- | --- | --- |
| 锁定中途插入/拔出显示器 | 窗口自动重排：新屏立即被纯黑窗口覆盖；移除的屏窗口销毁，不越界、不残留 | 插拔后所有屏幕仍被覆盖，无桌面泄露 |
| 副屏也想看时间（P1） | 设置中可选策略：`主屏时钟+副屏黑`（默认）/ `全部同内容` / `仅指定显示器` | 切换策略后下次锁定生效 |
| 不同分辨率/DPI 混合 | 时间字号按各屏视口独立计算（clamp 规则见 interaction-ui.md 2.4） | 1080p + 4K 混合时两屏时间视觉大小一致 |
| 熄屏/唤醒 | 作用于全部显示器 | 所有屏幕同灭同亮 |

## 2. 断电重启与崩溃恢复

**原则：安全但绝不把用户锁在外面。**

| 情形 | 期望行为 | 验收标准 |
| --- | --- | --- |
| 断电/强制重启后开机 | 默认恢复为 `active`（不自动锁定）；应用随用户手动/自启（P1）启动后 HTTP 服务就绪；配置、token、图片全部保留 | 重启后手机控制台可正常连接；未出现锁定窗口 |
| 用户希望开机即锁 | P1 提供"启动后自动锁"开关（默认关） | 开启后启动 30 秒内进入锁定状态 |
| 锁定窗口进程崩溃 | 进程内监督自动重建锁定窗口；若 5 秒内无法恢复则回退为 `active` 并记录错误日志（宁可放开也不卡死在黑屏） | 注入崩溃后 5 秒内恢复锁定或明确回到 active |
| HTTP 服务崩溃 | 自动重启监听；重启后 token 鉴权照旧 | 注入崩溃后 5 秒内 `/healthz` 恢复 200 |
| 熄屏状态断电重启 | 重启后显示器点亮、状态 `active` | 不出现"开机即黑屏无响应" |
| 系统休眠拦截失败 | 熄屏期间持续请求阻止系统挂起；若被系统策略强制休眠，唤醒后服务自动恢复，控制台显示离线→在线过渡 | 休眠唤醒后 10 秒内轮询恢复 |
| 时钟漂移 | 时间显示直接读系统时钟，每秒重读；系统时区/时间变化即时跟随 | 锁定状态下修改系统时间，显示随之更新 |

## 3. token 泄露处理

**威胁模型**：token 是唯一凭证，任何拿到 token 的局域网设备都能锁屏/熄屏/改设置（读不到用户文件，但可造成干扰）。

| 场景 | 处置流程 | 验收标准 |
| --- | --- | --- |
| 怀疑 token 泄露（手机丢失/借出/换机） | 电脑端 设置 → 安全 → **重置 token** → 二次确认（红字说明"所有已配对手机将失效"）→ 旧 token 立即失效 → 展示新二维码/配对码 | 重置后旧 token 请求返回 401（错误码 40102）；新 token 可正常使用 |
| 旧手机侧的表现 | 任意接口 401 → 控制台清除本机 token → 跳转配对页提示"配对已失效，请重新配对" | 无死循环、无白屏 |
| 多设备场景（P1） | token 按设备独立签发并可命名/单独吊销，丢失哪台吊销哪台，不影响其他设备 | 吊销 A 设备后 B 设备不受影响 |
| 日志审计 | 操作日志含来源 IP；异常高频鉴权失败（触发限速）在日志中告警标记 | 日志可查到 429 事件与来源 IP |
| 预防措施 | token 不回显、日志脱敏（前 4 位）、配置文件权限限当前用户（P1 迁移系统凭据库） | 见 PRD 6.1 S-01/S-05/S-11 |
| 局域网嗅探风险披露 | 一期 HTTP 明文，README 安全章节必须写明"token 可被同网段嗅探，请在可信网络使用，P2 提供 HTTPS"；建议用户路由器开启 AP 隔离 | README 含该风险说明 |

## 4. 升级策略

### 4.1 版本与发布

- 版本号：`vMAJOR.MINOR.PATCH`，语义化；一期从 `v0.1.0` 起，M1 Gate 达成后发 `v1.0.0`。
- 发布方式：推送 git tag `v*` → GitHub Actions 自动构建（Tauri 2 官方 action）→ 创建 GitHub Release。

### 4.2 "只保留一个安装包"的发布策略（来源：用户原始需求）

| 规则 | 说明 |
| --- | --- |
| 每次发版产物 | 每个**受支持平台**恰好一个安装包：一期 Windows 为 `remote-screen-lock_<版本>_x64-setup.exe`（NSIS 或 MSI 二选一，不重复出包）；macOS（P1）为 `.dmg`；不额外上传 zip/裸 exe/符号文件到 Release 资产 |
| 清理旧版 | CI 在发布新版本时删除旧 Release 的安装包资产（保留 Release 说明本身），保证**"下载入口任意时刻只有一个（每平台）安装包**"；同时将旧 Release 标记为非 latest |
| 单一入口 | README 下载徽章/链接指向 `releases/latest/download/<固定文件名>`，固定文件名不含版本号（CI 构建后重命名），用户永远点同一个链接拿最新包 |
| 源码包 | GitHub 自动生成的 Source code 不计入"安装包" |

### 4.3 配置兼容

| 规则 | 验收标准 |
| --- | --- |
| 配置目录与安装目录分离（Windows：`%APPDATA%/remote-screen-lock/`），覆盖安装不丢 token/设置/图片 | 覆盖升级后无需重新配对 |
| 配置文件带 `config_version` 字段；升级时按迁移规则升级旧配置，未知字段保留不删除 | 跨版本升级配置自动迁移，日志记录迁移动作 |
| 不兼容变更（配置无法迁移）时：启动弹窗说明并生成 `config.backup.toml`，然后以默认配置启动 | 旧配置文件可找回 |

### 4.4 更新通知（P2）

- Tauri updater 对接 GitHub Release；检查更新为手动触发（设置页"检查更新"按钮），默认不自动下载；更新前展示版本变更说明。

## 5. 已知系统限制 FAQ（面向最终用户，README 可直接摘编）

| 问题 | 答案 |
| --- | --- |
| 为什么开了系统锁之后，手机"解锁"只到系统登录界面？ | Windows/macOS 的安全设计：系统登录密码必须在本机输入，任何正规软件都无法（也不应该）远程绕过。想远程完全解锁，请在设置中关闭"系统锁"（安全性降低，自担）。 |
| 能不能锁我安卓手机的屏幕？ | 不能。安卓系统不允许第三方应用替换系统锁屏（来源：已定技术方向中的系统限制说明）。本项目里手机是"遥控器"，用于控制电脑。 |
| 熄屏后电脑会不会休眠失联？ | 被控端在熄屏期间会阻止系统休眠。若你的电源计划/组策略强制休眠，仍可能失联，建议将系统设置为"永不睡眠"（插电时）。 |
| 外接显示器亮度调不动？ | 部分外接显示器不支持软件调光（DDC/CI 未开启或不支持），接口会返回"不支持"，属预期行为。 |
| 公司电脑装了会被拦截吗？ | 企业杀软/组策略可能拦截端口监听或屏幕电源命令，此时操作返回失败并在诊断日志可见；请与 IT 确认放行。 |
| 换了路由器/网段变了怎么办？ | 被控端局域网地址变化后，手机重新扫码或手动输入新地址即可（token 不变）。P2 的 mDNS 自动发现将免去手动输入。 |
